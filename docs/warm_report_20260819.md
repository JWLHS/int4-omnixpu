# wa4/tint4 冷启动 vs 预热 全量对比报告（2026-08-19，WebSocket 精确计时）

- 环境：Arc A770 16GB，ComfyUI + 融合加载器（ComfyUI-Int4OmniXPU），AIMDO 启用。
- 流程：每个模型**冷启动跑 1 次 → 同模型紧接再跑 1 次（中间不清理）→ /free 卸载 → 下一模型**；每步耗时由 /ws progress 消息精确计时（毫秒级）。
- 参数：1024×1024、全部 **8 步**、cfg=1.0、euler/simple；冷 seed=20260819，热 seed=20260820（换 seed 绕过 ComfyUI 节点缓存，否则同输入直接缓存命中、不会真正采样）。
- 口径：wall=WS execution_success 时刻−提交时刻；prewarm=采样前权重搬运；**avg步=采样段÷8**（冷运行采样段已减 prewarm，但仍含首步 onednn JIT 编译，故冷 avg 步偏大；热运行无 prewarm 无 JIT）；**steady=第 2-8 步平均**（剔除含 prewarm/JIT/回搬的首步），是真正的稳态每步耗时。

## 4. 关键结论

- **热运行完全跳过 prewarm**：同模型两次之间不清理时模型保持驻留，无 CPU 重打包、无 onednn JIT 编译；热运行 wall 比冷运行快 9-30s，差异 = prewarm + 冷首步 JIT。
- **热运行首步仍偏高**（如 qwedit 冷首步 37.9s → 热首步 4.8s）：插件 detach 时把 GPU 权重释放回 CPU，热首步在采样中惰性回搬（显存 ~3GB→~10.7GB），但无 JIT；小模型（zit/zib ~120-150 层）热首步 1.6-1.9s，几乎与稳态持平。
- **稳态每步（第 2-8 步平均）**：冷热一致；wa4 与 tint4 同基底基本相当，但 **QW 系 wa4 明显快于 tint4**（qwaio 热 steady 1.49s vs 2.09s，qwedit 1.51s vs 1.50s 接近）；kr2 系两格式相当（wa4 ~1.8s vs tint4 ~1.9s 平均，且都呈快慢交替）。
- 部分模型存在**快慢交替步**（kr2 系 1.7/2.2s、zit/zib 系 0.93/1.35s、f2k 系偶发 0.42s），冷热一致，属模型/采样器结构行为而非缓存。
- 显存/共享显存为窗口峰值（GPU 计数器约 3.5s 采样间隔，短时尖峰可能低估）；窗口 epoch_start-2s ~ epoch_done+2s。
